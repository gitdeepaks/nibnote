# Nibnote

An iPad-only handwritten notebook built on Apple PencilKit: instant ink, fast tool switching, and notes that work fully offline, with optional sync.

> **Status:** Phase 0 (foundations and PencilKit spike). See [`docs/BUILD_PLAN.md`](docs/BUILD_PLAN.md) for the full plan, phase by phase, from setup to App Store.

## Stack

| Layer        | Choice                                                                                                          |
| ------------ | --------------------------------------------------------------------------------------------------------------- |
| App          | Expo SDK 58 (React Native 0.88), dev client, Expo Router                                                        |
| Ink          | PencilKit through a local Swift Expo module (Phase 1)                                                           |
| API          | Hono on Bun                                                                                                     |
| Shared types | Zod schemas and branded IDs in `packages/shared`                                                                |
| Tooling      | Bun workspaces, TypeScript 6 (strict), ESLint (typescript-eslint `strictTypeChecked`), lefthook, GitHub Actions |

## Requirements

- macOS with **Xcode 27** and the iPadOS 27 SDK
- **Bun 1.4** (package manager, scripts, tests)
- **Node 24 LTS** (`.nvmrc`); Expo CLI and Metro run on Node
- An iPad on **iPadOS 26 or later** with Developer Mode on (to run on a device)
- Optional: **SwiftLint 0.65+** for the native module lint

## Getting started

```sh
bun install          # installs every workspace and sets up the lefthook git hooks
bun run typecheck    # tsc in every package
bun run lint         # eslint --max-warnings 0 --no-inline-config in every package
bun run test         # bun test in every package
```

Run one package's script with `bun run --filter @nibnote/<package> <script>`.

### API server

```sh
bun run --filter @nibnote/server dev    # http://localhost:8787/health
```

### iPad app

```sh
cd apps/ipad
bunx expo run:ios --device     # build, sign and install the dev client on a connected iPad
bunx expo start --dev-client   # later sessions: start Metro only, then open Nibnote on the iPad
```

Add Expo or React Native dependencies with `bunx expo install <package>` so the versions match SDK 58.

#### First run on a physical iPad

1. Connect the iPad by cable, tap **Trust This Computer**, and turn on **Settings → Privacy & Security → Developer Mode**.
2. In Xcode go to **Settings → Apple Accounts** and add your Apple ID. A free **Personal Team** is enough for development. Set its ID as `ios.appleTeamId` in `apps/ipad/app.json`.
3. For a new bundle ID, create the provisioning profile once, because `expo run:ios` doesn't pass `-allowProvisioningUpdates`:
   ```sh
   cd apps/ipad/ios
   xcodebuild build -workspace Nibnote.xcworkspace -scheme Nibnote -configuration Debug \
     -destination 'id=<iPad UDID>' -allowProvisioningUpdates
   ```
4. When macOS asks for keychain access for `codesign`, enter your Mac login password and choose **Always Allow**. Frameworks are signed in parallel, so a dismissed prompt can leave one unsigned, and the install then fails with `ApplicationVerificationFailed`.
5. On the iPad, trust the developer in **Settings → General → VPN & Device Management**. When Nibnote asks to find devices on the local network, tap **Allow** so it can reach Metro.

Builds signed with a free Personal Team expire after 7 days. Run `bunx expo run:ios --device` again to refresh.

## Project structure

```
apps/
  ipad/        Expo app (iPad only). Routes in src/app/, native modules in modules/
  server/      Hono API on Bun; exports AppType for the typed Hono RPC client
packages/
  shared/      Zod schemas, branded IDs, Result, assertNever (the only home for shared types)
  config/      tsconfig base, ESLint rules, the lint-contract test, the Claude Code hook script
docs/
  BUILD_PLAN.md
.github/workflows/ci.yml    typecheck, lint, test (Ubuntu) + SwiftLint/XCTest (macOS)
```

`apps/ipad/ios/` is generated by `bunx expo prebuild` and is not committed. Configure native settings in `app.json` or config plugins.

## Type-safety contract

The code never uses `any` or `unknown`, `as` casts (except `as const`), `!` non-null assertions, or `@ts-ignore`. Every external value (JSON, env vars, route params, native events, `catch` errors) is parsed with a Zod schema on the same line.

The tooling enforces this, not code review:

- `packages/config/eslint.ts`: the contract rules, all errors
- `packages/config/lint-contract.test.ts`: lints a fixture of deliberate violations and fails if any rule stops working
- **lefthook** pre-commit: typecheck and lint for each package with staged files
- **Claude Code** `PostToolUse` hook (`.claude/settings.json`): typecheck and lint for the package of every edited file
- **CI**: the same checks on every push and pull request

Swift code follows SwiftLint's `force_cast`, `force_try`, `force_unwrapping` and `implicitly_unwrapped_optional` rules as errors (`.swiftlint.yml`).
